# Dirigo — архитектура

## Стек и обоснование

| Решение | Почему |
|---|---|
| **Bun** (runtime + сервер) | Нет node/python/dotnet в системе; bun = один бинарник; встроенные HTTP/SQLite/файлы; ~30–50 МБ RAM на процесс; запуск < 100 мс |
| **Ноль npm-зависимостей** | Установка/сборка не может сломаться; нет supply-chain; обновлять нечего |
| **Vanilla JS SPA** (1 html + 1 js + 1 css) | Без сборки, без фреймворка; обновляется на лету; ~0 МБ |
| **SSE (Server-Sent Events)** | Односторонняя трансляция событий сервер→UI; встроено в браузер; WebSocket не нужен (ввод — обычные POST) |
| **JSON-хранилище** (`data/db.json`) | Читаемо человеком, атомарная запись (tmp+rename); при росте — миграция на `bun:sqlite` (уже встроен, смена ~1 файла) |

## Поток данных

```
Браузер (web/index.html)
   │  REST: POST /api/sessions, /stop, /messages ...
   ▼
Bun-сервер (src/server.ts)
   │  store.ts  → data/db.json (sessions, messages, projects)
   │  runner.ts → Bun.spawn(CLI агента) в cwd проекта
   │                ├── stdout/stderr → logs/<sessionId>.log + SSE-события
   │                └── exit → статус done/error
   ▼
CLI агента (opencode/kilo/devin/...)
```

## Состояния сессии

`queued → running → done | error | stopped`
(остановка: kill дочернего процесса + пометка `stopped`)

## Файловая структура

```
dirigo/
├── src/
│   ├── server.ts          # HTTP-роуты + SSE-шина + статика
│   ├── store.ts           # JSON-хранилище + события
│   ├── agents/
│   │   ├── registry.ts    # описание агентов (id, команда, buildArgs)
│   │   └── runner.ts      # spawn/stop/логи (итерация I3)
├── web/
│   ├── index.html
│   ├── app.js
│   └── style.css
├── data/                  # db.json, logs/*.log (создаётся в рантайме)
├── docs/                  # план, архитектура, ресёрч, статус
└── start.ps1              # запуск одной командой
```

## Безопасность (важно!)

- Сервер по умолчанию `127.0.0.1:7171` — доступен только с этого ПК.
- Реквизиты агентов (API-ключи) **не** хранятся в dirigo — агенты используют свои.
- Экспозиция наружу (если понадобится): туннель + пароль сервера
  (`DIRIGO_TOKEN`), или Tailscale. Без аутентификации в интернет **не** выставлять:
  агенты исполняют произвольные команды в оболочке.

## Точки расширения

- Новый агент = запись в `registry.ts` (+ при необходимости адаптер в `runner.ts`).
- Новое хранилище = заменить `store.ts` на `bun:sqlite` (API compose/select уже изолирован).
- Веб-часть не требует сборки: правишь `web/app.js` — обновляешь страницу.
