# dirigo-site — лендинг Dirigo

Публичная страница продукта: позиционирование, проблема, как работает,
три отличия, доказательства (провенанс), периметр (шлюз персональных данных
и база знаний), режимы, агенты, удалённый доступ, безопасность, установка,
цены и FAQ. Одна HTML-страница, один CSS, один JS. Без сборки.

Главное сообщение страницы — не «параллельные агенты», а **запись о
происхождении кода**: Dirigo стоит внутри цикла генерации и поэтому может
выдать доказательство того, кто написал какие строки. Постфактум такая
запись не восстанавливается (см. `.memorybank/90-strategy-pivot.md`).

## Жёсткие правила

- **Ноль внешних запросов.** Ни CDN, ни шрифтов с чужих доменов, ни трекеров,
  ни аналитики. Шрифты системные, иконки и схемы — инлайн-SVG и CSS.
  Страница обязана открываться офлайн; это проверяет гейт.
- **Ноль зависимостей.** Ни `package.json`, ни `node_modules` в каталоге сайта.
  Нужен только Bun (локальный предпросмотр и тесты).
- **Только проверяемые утверждения.** На странице не должно быть ничего,
  что нельзя воспроизвести на чистой машине. Нереализованное помечается
  бейджем «скоро» или вынесено в Enterprise как private beta.
- **RU — основной язык**, EN — переключателем в шапке. Любой текст на странице
  несёт `data-i18n`, перевод лежит в словаре `assets/app.js`.

## Что на странице говорится — и почему именно так

| Блок | Утверждение | Основание |
|---|---|---|
| Hero | «запись о том, кто написал каждую строку, создаётся в момент, когда её пишет агент» | `.memorybank/90-strategy-pivot.md`: запись должна создаваться внутри цикла генерации, постфактум её не собрать |
| Бейджи | 27 тест-сьютов · релизный гейт · ноль npm-зависимостей · MIT | `.memorybank/10-release-audit.md` (прогон гейта на Linux) |
| Отличия | provisioning в один клик; ревью-гейт с автовозвратом; провенанс — подписанная запись о каждом изменении от ИИ | `.memorybank/10-release-audit.md` + `92-provenance.md` |
| Доказательства | состав пакета, git-трейлеры, выгрузка для аудита, обнаружение подделки журнала | `.memorybank/92-provenance.md` (код, API и тесты, в т.ч. `e2e-evidence`, который ловит подделку) |
| Периметр | четыре режима шлюза (off/warn/redact/block); найденные значения не хранятся нигде | `92-provenance.md`, `src/policy.ts` |
| База знаний | выключена по умолчанию, уходит на ваш приёмник, обязательно через шлюз | `92-provenance.md`, `src/knowledge.ts` |
| Агенты | 13 агентов в реестре | подтверждено на Linux, `.memorybank/10-release-audit.md` |
| Установка | «регулярно проверяется на Linux; macOS и Windows — тот же бандл» | Linux проверен вживую; про остальные платформы сильнее заявлять нельзя |
| Enterprise | «private beta, набираем design-партнёров»; построены провенанс и шлюз, не построены SSO/SCIM, интерфейс журнала аудита, ролевые политики и SLA | `92-provenance.md` — шлюз и провенанс **есть**; остальное проектируется с партнёрами |
| FAQ | «пользователей пока нет» | проект только выходит в открытый доступ |

Про провенанс нельзя заявлять соответствие GDPR или какой-либо сертификации:
построены журнал, подпись, трейлеры, выгрузка и шлюз — и ровно это на странице
и написано. Гейт проверяет это отдельной проверкой.

Чего на странице нет и быть не должно: имён конкурентов, сравнений «мы лучше
чем …», выдуманных метрик, логотипов клиентов, отзывов, старого имени продукта.

## Файлы

```
index.html                     — вся страница
assets/style.css               — дизайн-система: токены, компоненты, темы, адаптив
assets/app.js                  — i18n (RU/EN), темы, FAQ, табы режимов, схема режимов,
                                 интерактивный макет пульта, клипы, копирование команды,
                                 форма design-партнёрства (mailto, без отправки со страницы)
assets/art/diff.png            — единственный реальный скриншот на странице
assets/art/logo.svg            — знак
assets/og.png                  — OG-картинка, генерируется из og-preview.html
og-preview.html                — исходник OG-картинки (утилита, не индексируется)
serve.ts                       — локальный предпросмотр (Bun, порт 7380)
tests/site-check.ts            — статический гейт (132 проверки)
tests/site-e2e.ts              — E2E в браузере: RU/EN, темы, интерактив, мобильный вид
tests/site-geom.ts             — геометрия, вертикальный ритм, контраст WCAG, скриншоты
```

## Команды

```bash
export PATH="$HOME/.bun/bin:$PATH"

bun run serve.ts              # предпросмотр http://127.0.0.1:7380
bun run tests/site-check.ts   # статический гейт        → 132/132
bun run tests/site-e2e.ts     # браузерный E2E          → 95/95
bun run tests/site-geom.ts    # ритм, контраст, съёмка  → 14/14
```

E2E и geom поднимают предпросмотр сами и ищут Chromium от Playwright
(`~/.cache/ms-playwright`, `%LOCALAPPDATA%\ms-playwright`) либо системный Chrome.
Браузера нет — тест честно пишет `skip` и выходит с кодом 0.
Путь к браузеру можно задать явно: `PLAYWRIGHT_CHROMIUM=/path/to/chrome`.
Скриншоты geom кладёт в `SHOT_DIR` (по умолчанию временный каталог).

## Что обновлять перед публичным запуском

- [ ] **Переснять скриншоты** итогового UI (сейчас на странице один настоящий кадр — `diff.png`, остальное собственные HTML-макеты).
- [ ] **Домен.** В `index.html` зашит `https://dirigo.cortexally.ai` (canonical, команды
      установки). Если домен другой — поменять там и в `DEPLOY.md`.
- [ ] **Почта для заявок.** В `assets/app.js`, `initEnterpriseForm`, константа
      `MAILBOX = "partners@cortexally.ai"` — подставить рабочий ящик.
- [ ] **Ссылка на репозиторий.** `https://github.com/cortexally/dirigo` —
      подтвердить, что организация и репозиторий созданы.
- [ ] **Лицензия.** Страница говорит MIT. В репозитории продукта лицензия
      указана в двух местах по-разному (MIT в `LICENSE`, Apache-2.0 в
      позиционировании v2) — выровнять до запуска, иначе утверждение на
      лендинге станет неверным.
- [ ] **install.sh / install.ps1 и бандлы** должны отдаваться с того же домена
      по https (см. `DEPLOY.md`), а не с чужого домена-заглушки.
